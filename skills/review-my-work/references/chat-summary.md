# Concise chat summary

After writing the report, summarise the result naturally in one to four short lines.
Lead with the score, assessability and any merge block. Then name the main reason and
the first useful repair. If more actionable findings remain, say how many and ask
whether the developer wants them explained briefly.

Do not copy a fixed format. These are examples of density and tone, not templates.
Use a link only when it has a verified stable target in the current renderer, such
as the exact rubric criterion or evaluation question. If the target or anchor is
uncertain, omit the link.

**Example 1**

Score: 7.4/10 · 89% assessable. The score is mainly lower because the criteria were
recorded late and several tests were never shown to detect a real fault. Add one
negative control per important criterion. I found three smaller improvements too;
shall I explain them briefly?

**Example 2**

Score: 8.8/10 · fully assessable · merge clear. The implementation and tests match
well; the main gap is evidence tied to this commit. Record the failing and passing
runs with the commit ID. There are two smaller points—shall I explain them briefly?
